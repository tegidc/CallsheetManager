02

Short fields on Shoot Days

You liked how Tech Specs handles short inputs and want the same on Shoot Days. Those two screens currently use different systems, and it's worth being precise about why.

Tech Specs — what you like
.ts-grid flex-wrap + .ts-field. Label beside a box sized to the value. Fields flow and wrap; no fixed column.
Shoot Days — current
.grid.g4. Four equal columns, label stacked above a full-cell-width box. I left these stacked last round because a fixed 104px label column left only ~55px for the control.
Why the Tech Specs pattern works here and the fixed label column didn't: .ts-field doesn't reserve a label column at all — each field is only as wide as its own label plus its own box, and rows wrap naturally. So "Day #" gets a small box and "All-crew call" gets a slightly bigger one, instead of every field being forced into an identical quarter of the row.
A — Tech Specs pattern applied suggested
Day details and Weather become .ts-grid. Everything on one line where it fits, wrapping when it doesn't, each box sized to its value.
B — leave as is
Keeps the rigid four-up grid. Predictable, but the boxes are all the same width regardless of whether they hold "1" or a date.

Apply the Tech Specs pattern to Shoot Days short fields?

This would cover the Day details row (Day # / of / Shoot date / All-crew call) and the Weather row (Temp / Precip / Condition / Sunrise-Sunset). Long fields — brief, parking, notes — stay full-width, which is what they want.

A — always an input suggested

Make "Show as" a plain input?

One consequence worth naming: with an always-live input the field saves when you click away rather than when you press a button, so there's no explicit confirmation. On a row of 66 people that's less clicking, but it also means an accidental keystroke saves silently. Tell me in the notes if you'd rather it saved only on Enter and blur-with-change.
