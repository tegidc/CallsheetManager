You asked whether the site is really "a few datasets and lookup tables plus styling" carrying accumulated baggage. Measured answer: your instinct is right, but the weight isn't where you'd guess. The actual lookup tables are ~135 lines — one percent. The single biggest weight is prose: a third of the file is written history of its own construction ("in Phase X this moved because…"), maintained in parallel with MAP.md — which already records the same reasoning and is where it belongs.

The baggage you suspected is real and is the second biggest weight: the same jobs built independently several times — 11 hand-built tables/grids (Roles has the best one; the others each reinvent it), 5 separate "estimate with an override" systems (crew rates, location costs, tech specs, cameras, day overrides), 3 filter panels (why the filter changes shape between tabs), 2 calendars, and 5 different routes to create a shoot day. That's ~1,800 lines that could be ~700 — and it's also why tabs drift apart visually: each copy evolves alone.

A lean rebuild with identical features would be roughly 3,500 lines — a quarter of today's size. That's not a recommendation to rebuild (your iterative approach is working); it's the honest measure of how much of the file is baggage versus brain.

Part 3 One thing you should know about before anything else

The database is currently open to the public, and so is the AI chat. This isn't a bug from this week — it's how the project was originally set up. The site is a public page, and the key it uses to talk to the database is (by design, for this kind of setup) visible to anyone who views the page source. What's supposed to make that safe is rules on the database itself saying who can read and write. I checked the live rules: they currently say everyone may read and write everything.

In practice: anyone who found the site could read — or change — the whole crew database (phone numbers, home addresses, day rates, dietary needs, car registrations), every project and every budget. Notably, your .gitignore already keeps day-rate exports out of the public repo for exactly this reason — but the live database serves the same information to anyone who asks. The same applies to the AI chat: anyone could use it as a free door to your Anthropic account.

The fix is a proper login (email + password for you, and later maybe a second user), plus database rules that say "only signed-in users". That's decision D1 below — it needs your go-ahead because it changes how you open the app (one sign-in, remembered on your devices) and it touches the live database, which I won't do without you.
